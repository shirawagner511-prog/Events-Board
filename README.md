# לוח אירועים

אפליקציית ווב (מותקנת למסך הבית בטלפון) שמחליפה את לוח האירועים השבועי:
יהלי מעדכנת – וכולם רואים את השינוי מיד, כל אחד את מה שקשור אליו.

## מה יש באפליקציה

- **תצוגת יום / שבוע / חודש** + מתג **"שלי" / "הכל"** (משתמש יכול להיות משויך לכמה מחלקות).
- **כרטיס אירוע**: שם, תאריך, שעת יציאה/היערכות, התחלה, סיום, מקום, כמות אנשים, תפריט, מוציא, מקפל, ספקי חוץ, הערות, מזמין – ומשימה לכל מחלקה.
- **אישורים**: כל אחראי מסמן "ראיתי" ו"בוצע". אם האירוע או המשימה השתנו אחרי שאישר – זה מסומן "עודכן מאז שאישרת" ומבקש אישור מחדש.
- **התראות באפליקציה**: באנר אדום למשימות של היום/מחר שמחכות לאישור שלך; ליהלי – סיכום מה עוד לא אושר אצל הצוות.
- **אירועים צמודים**: סימון אוטומטי כשיש אירועים באותו יום בהפרש של פחות מחצי שעה.
- **זימוני Outlook**: כל אחראי מקבל זימון ליומן לשעת היציאה, עם המשימה שלו ותזכורת 30 דקות לפני. שינוי באירוע = הזימון מתעדכן; ביטול = הזימון נמחק.
- **monday**: טפסי "Playtika Event Form ISR" נמשכים כל 5 דקות לתיבת "ממתינים". כי הרבה אירועים נסגרים קודם בוואטסאפ, האפליקציה מציעה **לחבר** את הטופס לאירוע שכבר קיים (משלימה רק שדות חסרים) או לפתוח ממנו אירוע חדש. טופס שהשתנה אחרי החיבור מסומן לבדיקה.
- **הדבקת הודעה**: ביצירת אירוע אפשר להדביק הודעת וואטסאפ / מייל ו-Claude ממלא טיוטה (כולל משימות למחלקות) לבדיקה לפני שמירה.
- **הדפסה / PDF**: תצוגת הדפסה לדף A4 לרוחב - טבלה לכל יום, כל הפרטים, ותיבת סימון לכל משימה. אפשר להדפיס יום, שבוע, חודש או אירוע בודד, לפי הסינון הנוכחי.
- **קבצים מצורפים**: בעריכת אירוע מצרפים קבצים מהמחשב (תפריט מורחב, הצעת מחיר, תמונה) - עד 20MB לקובץ. בכרטיס האירוע הם נפתחים בלחיצה.
- **שינויים**: כפתור עם מונה של אירועים שהשתנו מאז הביקור הקודם במכשיר.
- **טיוטות**: אירוע נשמר כטיוטה (רק מנהלי הלוח רואים) עד שלוחצים "פרסום".
- **כניסה בקישור אישי** – בלי סיסמה. מנהל/ת לוח שולח/ת לכל אחד קישור בוואטסאפ מתוך מסך "אנשים"; אפשר לנתק ולהנפיק קישור חדש.

## טכנולוגיה

React + Vite + Tailwind (בדיוק כמו inventory_master), Supabase (Postgres + Realtime + Edge Functions), אחסון ב-Firebase Hosting.

```
src/                       האפליקציה
supabase/migrations/       סכמה, הרשאות (RLS) ופעולות
supabase/functions/        sync-monday · send-invites · parse-message
supabase/functions/_shared לוגיקה משותפת (זימונים, monday, זמנים) – עם בדיקות
```

## מצב דמו (בלי שרת)

```bash
npm install
npm run demo
```

נפתח ב-http://localhost:5173 עם נתוני דוגמה מלוח אוקטובר, ממוקמים סביב השבוע הנוכחי. אין צורך ב-Supabase או במפתחות.

- בפס העליון "צפייה בתור" מחליפים משתמש (יהלי, שירה, שגיא, ענבר, ליאל, לירן, ענת) ורואים מה כל אחד רואה.
- הכל נשמר בדפדפן. שתי לשוניות פתוחות מתעדכנות זו מזו בזמן אמת, כמו שיקרה בין טלפונים.
- זימוני Outlook לא נשלחים. מופיעה הודעה למי היו נשלחים (לפי אותה לוגיקה של הגרסה האמיתית).
- "משיכה מ-monday" מוסיפה טופס לדוגמה; "מילוי אוטומטי" מהודעה עושה פענוח בסיסי בלבד.
- "איפוס נתונים" מחזיר להתחלה.
- הפקודה פותחת גם כתובת ברשת המקומית (Network), כדי לנסות מהטלפון באותו Wi-Fi.

## הקמה (פעם אחת)

1. **Supabase**: לפתוח פרויקט חדש. ב-Authentication → Sign In / Providers להפעיל **Anonymous sign-ins**.
2. **סכמה**: להריץ ב-SQL Editor את הקבצים ב-`supabase/migrations` לפי הסדר, ואז את `supabase/seed.sql`. מיגרציה 0004 יוצרת גם את ה-bucket הפרטי `event-files` לקבצים.
3. **מנהלת ראשונה**: להעתיק את `supabase/bootstrap-admin.example.sql` ל-`supabase/bootstrap-admin.sql` (לא נכנס ל-git), למלא, להריץ, ולפתוח את הקישור שמתקבל. את שאר הצוות מוסיפים מהאפליקציה (👥).
4. **Edge Functions**: `supabase functions deploy sync-monday send-invites parse-message` ולהגדיר secrets:
   | משתנה | למה |
   |---|---|
   | `MONDAY_API_TOKEN`, `MONDAY_BOARD_ID` (1795196643) | משיכת טפסים |
   | `ANTHROPIC_API_KEY` | הדבקת הודעה → טיוטה |
   | `APP_URL` | קישור מהזימון חזרה לאירוע |
   | `MAIL_TRANSPORT` = `graph` / `mailgun` / `log` | שליחת זימונים (`log` = לא שולח) |
   | `MAIL_FROM`, `MAIL_FROM_NAME` | כתובת השולח |
   | `GRAPH_TENANT_ID`, `GRAPH_CLIENT_ID`, `GRAPH_CLIENT_SECRET` | ל-`graph`: אפליקציה ב-Entra עם הרשאת Mail.Send (דורש אישור IT) |
   | `MAILGUN_API_KEY`, `MAILGUN_DOMAIN` | ל-`mailgun` |
5. **סנכרון monday אוטומטי**: להריץ את `supabase/cron.sql` (אחרי מילוי הכתובת והמפתח).
6. **אתר**: ליצור `.env` לפי `.env.example`, ואז `npm run build && firebase deploy`.

## פיתוח ובדיקות

```bash
npm install
npm run dev
npm run test:ui     # לוגיקה + זימונים + מיפוי monday
npm run test:db     # הרשאות ופעולות מול Postgres מקומי (TEST_DATABASE_URL, ברירת מחדל localhost)
```

`db:reset` מוחק את כל הסכמה – הוא מסרב לרוץ מול מסד שאינו מקומי, אלא אם מגדירים `ALLOW_REMOTE_DB_RESET=1`.
